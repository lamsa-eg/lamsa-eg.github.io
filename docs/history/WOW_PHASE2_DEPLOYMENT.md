# LAMSA WOW ✦ — Phase 2 on V28

المرحلة الثانية مبنية فوق **WOW Phase 1** وتضيف تجربة **كشف نوع المولود المتزامنة** دون تغيير سلوك الذكريات العادية.

## ما تم تنفيذه

- لوحة داخل محرر الذكرى لاختيار «بنوتة / ولد» وكتابة رسائل النتيجة.
- النتيجة تُحفظ في جدول محمي مستقل، ولا تُخزن داخل `memory_wow_moments.config`.
- صفحة الذكرى تستقبل النصوص العامة فقط؛ لا تستقبل النتيجة قبل لحظة الكشف.
- المرسل يبدأ اللحظة من صفحة متابعة الطلب.
- السيرفر يحدد وقتًا واحدًا للكشف بعد 12 ثانية، وتستخدم الأجهزة `serverNow` لضبط العد.
- كل جهاز يطلب النتيجة بعد انتهاء التوقيت؛ الاستجابة قبل الموعد لا تحتوي مفتاح `result` أصلًا.
- عداد تقريبي للأجهزة الموجودة خلال آخر 45 ثانية.
- إعادة الضغط على بدء الكشف لا تنشئ موعدًا جديدًا ولا تغيّر الموعد الأصلي.
- حركة خفيفة وكونفيتي، مع دعم `prefers-reduced-motion`.

## ترتيب النشر الآمن

1. نفّذ متطلبات نشر Phase 1 أولًا، مع إبقاء `WOW_ENABLED=false` أثناء التجهيز.
2. طبّق `supabase/migrations/20260925_lamsa_wow_phase2.sql`.
3. انشر Edge Functions المحدثة، وبالأخص:
   - `public-memory`
   - `wow-admin-config`
   - `wow-sender-subscribe`
   - `wow-gender-reveal`
4. ارفع ملفات Cloudflare Pages الجديدة.
5. اختبر ذكرى تجريبية منشورة على جهازين على الأقل.
6. بعد نجاح الاختبارات، غيّر `WOW_ENABLED=true`.

> لا تنشر `wow-admin-config` أو `wow-gender-reveal` قبل تطبيق Migration المرحلة الثانية؛ كلاهما يعتمد على الجداول الجديدة.
